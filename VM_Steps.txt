LOCAL - Tag Docker 
----------------------
docker build -t backend:latest -f backend/backend.dockerfile ./backend


LOCAL - Subir Tag a GCP
--------------------------
docker tag relational_db:latest us-central1-docker.pkg.dev/desarrollo-web-451923/cloud-images/relational_db:latest

gcloud auth activate-service-account --key-file=key.json
gcloud auth configure-docker us-central1-docker.pkg.dev
docker push us-central1-docker.pkg.dev/desarrollo-web-451923/cloud-images/relational_db:latest


GCP - Configurar la VM
---------------------------
1. Dar permisos al 'Service account' (1005183810077-compute@developer.gserviceaccount.com) de:
    * Artifact Registry Reader
    * Editor
    * Service Usage Admin

2. Al crear la VM debemos:
    * Networking: Habilitar el tráfico necesario (o todo el HTTP y HTTPS).
    * Security: Seleccionar el 'Service account' con los permisos. Además, habilitar el API: 'Cloud Platform' (o todos)


GCP - VM (SSH)
-----------------
1. Configuraciones generales e instalar docker:
    * sudo apt-get update
    * sudo apt-get install -y docker.io docker-compose
    * sudo systemctl status docker
    * sudo docker network create private_network

2. Ingresamos al GCP-CLI para bajar images de docker.
    * gcloud auth list
    * gcloud config get-value project --> (Si no es nuestro proyecto: gcloud config set project desarrollo-web-451923)
    * gcloud auth configure-docker us-central1-docker.pkg.dev

3. Revisamos que tengamos permisos:
    * curl -H "Metadata-Flavor: Google" \
        "http://metadata.google.internal/computeMetadata/v1/instance/service-accounts/default/scopes"
    * gcloud artifacts repositories list

4. Revisamos que la imagen exista y cual es su tag
    * gcloud artifacts packages list \
        --repository=cloud-images \
        --location=us-central1
    * gcloud artifacts docker tags list us-central1-docker.pkg.dev/desarrollo-web-451923/cloud-images/relational_db

5. Damos autorización a la VM con el 'Service account' para que pueda correr imagenes:

    * TOKEN=$(gcloud auth print-access-token)
        echo $TOKEN | sudo docker login -u oauth2accesstoken --password-stdin https://us-central1-docker.pkg.dev

6. Corremos la imagen:

    ----------- RELATIONAL DB -----------
    sudo docker run -d \
        --name relational_db \
        --network private_network \
        -e POSTGRES_DB=USER \
        -e POSTGRES_USER=team5 \
        -e POSTGRES_PASSWORD=Project2025! \
        -e POSTGRES_PORT=5432 \
        us-central1-docker.pkg.dev/desarrollo-web-451923/cloud-images/relational_db:latest
        
    ----------- BACKEND -----------
    sudo docker run -d \
        --name backend \
        --network private_network \
        -p 8000:8000 \
        -e POSTGRES_DB=USER \
        -e POSTGRES_USER=team5 \
        -e POSTGRES_PASSWORD=Project2025! \
        -e POSTGRES_PORT=5432 \
        -e POSTGRES_HOST=relational_db \
        -e DATABASE_URL='postgresql://team5:Project2025!@relational_db:5432/USER' \
        -e SECRET_KEY=secret \
        -e FRONTEND_URL=http://34.171.248.204:3000 \
        us-central1-docker.pkg.dev/desarrollo-web-451923/cloud-images/backend:latest


    ----------- FRONTEND -----------
    docker build --no-cache -t frontend:latest --build-arg VITE_API_BASE_URL=http://34.30.75.41:8000 -f frontend/frontend.dockerfile ./frontend

    sudo docker stop frontend
    sudo docker rm frontend
    sudo docker image prune -a

    sudo docker run -d \
        --name frontend \
        --network public_network \
        -p 3000:3000 \
        us-central1-docker.pkg.dev/desarrollo-web-451923/cloud-images/frontend:latest


7. Revisar que este corriendo:
    * sudo docker ps
    * sudo docker rm -f backend
